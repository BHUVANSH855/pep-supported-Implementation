# packaging.tags Issue #311

**URL:** https://github.com/pypa/packaging/issues/311
**Status:** Partially resolved — pp3-none-any added in packaging 21.3
**Identified by:** Eli Schwartz in the Requires-Implementation thread

## What the issue documents

packaging.tags did not support *-none-any wheels for non-py* interpreter
tags. This means cp3-none-any is not generated by packaging.tags.

pp3-none-any was added as a special case after this issue.
cp3-none-any is still not generated as of September 2026.

## Relevance to this proposal

When reviewers say "just use implementation-specific wheel tags for
pure-Python packages," this issue shows the tooling to support that
approach is incomplete.

Specifically: a pure-Python CPython-only package cannot today easily
publish a cp3-none-any wheel because:

1. packaging.tags does not generate cp3-none-any in its tag set
2. The tooling to produce such wheels is not standardized
3. Only pp3-none-any was added as a special case

## How to use this in discussions

Do not say "wheel tags are broken" — that overstates it.

Do say: "The tooling for implementation-specific none-any wheels is
incomplete. cp3-none-any is not currently generated by packaging.tags,
which means the 'just use wheel tags' answer has a practical gap for
pure-Python implementation-specific packages."
